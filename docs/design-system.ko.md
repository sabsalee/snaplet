# Snaplet 앱 디자인 기준 · v0.8

## 이번 단계의 범위

편집창뿐 아니라 시작 화면, 설정, 미리보기, 고정 이미지, OCR, 긴 화면 캡처, 오류 안내에 공통 디자인을 적용한다. Windows 창 조작·한국어 글자·키보드 포커스에 맞춘다.

## 공통 기준

- 색: 중립적인 어두운 배경 `#191C21`, 카드 `#22262D`, 기본 글자 `#F0F2F6`, 보조 글자 `#A6AFBD`, 강조 `#7DAAFF`, 주 동작 `#315FCB`.
- 타이포그래피: Segoe UI 및 Windows의 한글 폰트 대체. 본문13px, 보조11–12px, 화면 제목24px, 시작 화면28px. 이미지에 저장하는 주석 글자와 앱 UI 글자는 별개다.
- 간격: 4/8/12/16/24/28px, 버튼 최소 높이36px. 입력창·버튼 모서리5–6px, 카드10px.
- 아이콘: Microsoft Fluent UI System Icons의 24 px regular 벡터를 사용한다. 원래 24 × 24 격자를 유지하며 텍스트·번호 도구도 같은 아이콘 계열을 쓴다. 라이선스는 앱에 포함한다.
- 상태: hover, 누름, 키보드 포커스, 비활성 상태를 구분한다. 색상 팔레트는 hover해도 색 자체가 바뀌지 않는다.
- 버튼·체크/스위치·입력창·드롭다운·슬라이더·스크롤바·메뉴·도움말을 같은 테마로 그린다. Windows 제목 표시줄도 어두운 색을 요청하며 시스템이 지원하지 않으면 기본 창 동작을 유지한다.

구현은 `src/Capture.Windows/UI/Theme.xaml`, `Ui.cs`에 모은다. 캡처 엔진이나 이미지 픽셀 처리와 테마를 섞지 않는다.

## 화면별 적용

| 화면 | 구성과 조작 |
| --- | --- |
| 시작 | 실제 설정의 단축키를 표시하는 캡처 카드, 이미지 열기·클립보드·도구 체험, 최근 캡처 최대4개 미리보기. 작은 창에서는 스크롤을 허용한다. |
| 설정 | 캡처/단축키/저장/정보 탐색. 스위치·단축키 recorder·폴더 선택, 저장/취소 버튼을 고정 하단에 둔다. 오류는 입력을 지우지 않고 화면 안에 표시한다. |
| 미리보기 | 이미지 중심의334px 카드. 편집·복사·저장·OCR·고정 아이콘. 편집하면 고정하지 않은 미리보기는 닫는다. 복사 중에는 작업 수명을 유지한다. |
| 고정 | 이미지 위에 header와 도구를 겹쳐 두고 hover 시 표시한다. 오른쪽 드래그 이동, 휠 크기 변경. 왼쪽 드래그는 PNG 전달을 유지한다. |
| 편집 | 기준 앱과 같은 한 줄 툴바(52px): 복사·저장 \| 고정 \| 파일 드래그 \| 선택·화살표·텍스트·사각형·가림·펜·(··· 에서 마지막으로 고른 도구)····, 오른쪽에 커서 아래 색(Tab 복사)·이미지 크기·확대율을 값+작은 설명 2줄로 표시하고 ≡ 이미지 메뉴(실행 취소·배경·자르기·내보내기)를 둔다. 속성은 툴바 아래 오른쪽에 떠 있는 둥근 패널: ‹ 접기 · 색 점 · 쐐기형 크기 슬라이더 · 아이콘 스타일(화살표 머리 4종, 도형 둥근 테두리/테두리/사선/채움, 텍스트 말풍선/일반) · ··· 추가 속성(프리셋·숫자 입력·말꼬리·모드). 상태 줄 대신 아래쪽에 잠시 나타나는 안내를 쓴다. Windows 앱 모드가 밝으면 밝은 테마, 어두우면 어두운 테마를 쓰고 설정이 바뀌면 바로 따른다. 속성 입력 컨트롤의 방향키는 객체 이동 단축키로 가로채지 않는다. |
| OCR | 수정 가능한 큰 텍스트 영역, 글자 수, 줄바꿈 합치기, 복사 피드백. 인식은 로컬이다. |
| 긴 화면 | 누적 높이,3단계 안내, 진행·성공·재시도 메시지, 추가/완료/취소 버튼. 자동 스크롤 기능을 추가한 것은 아니다. |
| 오류 | 같은 제목·설명·확인 버튼 구조로 안내. 파일·폴더 선택 같은 시스템 대화상자는 Windows 기본 동작을 사용한다. |

## 검증과 한계

Windows CI에서 합성 이미지만 사용해 각 창을 실제 WPF로 생성·배치하고 PNG로 렌더링한다. 시작 화면의 기본/최근/작은 창, 설정4개 페이지와 오류 상태, 미리보기/고정/hover, 편집(밝은 `editor-ui.png`, 어두운 `editor-ui-dark.png`), OCR, 긴 화면, 안내 창을 검토한다. 150% LayoutTransform 검사는 레이아웃 확대이며 실제 OS DPI 전환을 검증하지 않는다.

자동 검사는 캡처 명령 연결, 설정 탐색/유효성/변경 적용, 고정 전환, 편집 열기, OCR 줄바꿈 버튼을 routed event로 실행한다. 실제 사용자 화면을 촬영하거나 클립보드에 쓰지 않는다. 물리 마우스·키보드·한글 IME·혼합 DPI·캡처 속도는 이 검사의 범위가 아니다.

개발 호스트는 macOS다. GitHub Windows runner의 자동 검사와 원격 Windows의 실제 포인터 조작 검증은 구분해 기록한다. 자동 검사 통과만으로 사용자의 PC에서 모든 실사용 항목이 완료되었다고 표시하지 않는다.

## 다음 확인

실제 Windows11에서 제목 표시줄·키보드 메뉴·IME·배율 전환·고정 창 이동/크기를 확인한다. 그 이후 화면 간 간격과 도구 동작의 일관성을 확인한다. 손그림·정렬·돋보기·효과·이미지 구성 도구 간 조작과 상태 표시의 일관성도 확인한다.

Windows 창 속성 근거: [Microsoft DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute).

## 편집 피드백 기준

선택 전 호버 경계와 이동 커서로 객체임을 알린다. 텍스트 도구의 입력 커서는 기존 텍스트를 클릭해 편집하는 동작과 일치해야 한다. 선택 후 경계와 역할별 조절점을 제공한다. 조절점은 회색 테두리의 흰 둥근 사각형(100%에서 8px)이며 도형은 경계 6px 바깥에 8개, 화살표는 양 끝과 가운데에 둔다. 바깥 조절점을 잡아도 가장자리가 포인터로 튀지 않고 잡은 만큼만 움직인다. 핸들 hover는 화면 픽셀 기준의 halo와 하단 안내를 표시하며 객체가 바뀌지 않은 포인터 이동마다 전체 이미지를 다시 그리지 않는다.

기본 스타일은 바로 써도 균형이 맞는 굵기·색·둥글기를 제공한다. 프리셋 미리보기는 실제 내보내기와 같은 렌더러를 사용한다. 속성 수치는 슬라이더와 직접 입력을 함께 제공하고, 프리셋 적용 뒤에도 개별 속성과 Undo를 유지한다.
