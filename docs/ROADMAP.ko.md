# 로드맵 · 기준 앱 대비 기능 표

기준일: 2026-10-26. 비교 대상: 기준 앱 설치본과 공식 문서. 이 표가 남은 작업의 기준 문서입니다. 상태는 **완료**(코드+자동 검사), **부분**, **없음**, **보류**(의도적으로 미룸)로 적고, 실제 Windows 실기기 확인은 별도 열에 기록합니다.

## 진행 원칙

1. 원본 관찰(CUA 직접 조작) → REA 근거(가능하면 디컴파일러) → 명세 → 구현 → Windows CI → 실기기 확인 순서로 진행합니다.
2. 자동 검사 통과만으로 "완료"라고 쓰지 않습니다. 실기기 열이 비어 있으면 체감 검증 전입니다.
3. 원본 코드·자산은 복사하지 않습니다. 동작과 수치만 관찰해 새로 구현합니다(클린룸).
4. 말풍선·꼬리 모양 같은 미세 조정은 이 표의 큰 공백이 줄어들 때까지 보류합니다.

## 0단계 · 기반

| 항목 | 상태 | 비고 |
| --- | --- | --- |
| 설정 스키마 버전과 이전(단축키 추가 시 기존 설정 유지) | 완료 (0.9) | 이전 버전은 단축키 개수가 바뀌면 설정 전체를 버렸음 |
| 미지정 단축키, Backspace로 해제 | 완료 (0.9) | 새 명령은 미지정으로 시작 |
| REA 디컴파일러 연결 (Ghidra 12.1 + JDK 21 또는 Hopper) | 없음 | Mac에서 `rea doctor --provider ghidra`. 스크롤 정합·자동 선택 기준값 분석에 필요 |
| 실기기 검증 절차 고정 (원격 Windows 11, 릴리스마다) | 부분 | `runtime-validation.md` 체크리스트와 `capture-performance.jsonl` 중앙값·p95 기록 |
| 편집기 구조 분리 (도구별 geometry·상태 머신·속성 패널) | 없음 | 2단계 전에 진행 |
