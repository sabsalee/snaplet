# 동영상 녹화 계획

작성일: 2026-11-06. 상태: 제안. 아직 코드를 쓰지 않았고, 프로토타입도 돌려 보지 않았습니다.

## 결론

- **기준 앱에는 녹화 기능이 없습니다.** 공식 안내는 화면을 "녹화"하지 않고 스크린샷만 찍는다고 설명하고, 바이너리 문자열에도 영상 인코딩이나 녹화 저장 흔적이 없습니다. 움직이는 결과물은 두 프레임짜리 "Before/After GIF"뿐입니다. 녹화는 다른 앱을 참고해 독자적으로 설계합니다.
- **"녹화가 된다"만으로는 쓸 이유가 없습니다.** Windows 기본 캡처 도구도 이미 녹화와 잘라내기를 제공합니다. 첫 버전부터 Snaplet의 세 강점이 드러나야 합니다.
  - **빠른 속도:** 단축키에서 녹화 시작까지, 정지에서 공유까지 기다림이 거의 없음
  - **다양한 편집 도구:** 스크린샷용 화살표·번호·형광펜·모자이크를 영상에도 그대로 사용
  - **세련된 UI/UX:** 스크린샷과 같은 흐름과 디자인, 설명 없이 쓸 수 있는 녹화 도구막대
- **기술 기반은 그대로입니다.** Windows Graphics Capture(WGC)와 Windows 내장 인코더로 시작해 앱 크기 증가를 거의 없앱니다. 다만 위험한 부분은 코드를 쓰기 전에 실제 PC로 확인합니다.

## 벤치마크

직접 사용해 본 결과가 아니라 공개 자료 기준입니다. 판매사 자료와 제휴 블로그가 섞여 있어, 구현 전에 Windows에서 쓸 수 있는 앱은 직접 써 보고 수치를 재야 합니다.

| 앱 | 플랫폼 | 눈여겨볼 점 | 부족한 점 | Snaplet에 주는 시사점 |
| --- | --- | --- | --- | --- |
| Windows 캡처 도구 | Windows 11 내장 | 무료·기본 탑재, 녹화, 잘라내기, GIF 내보내기(버전에 따라 다름) | 여러 클립 잇기 불가. 소리 지원은 자료가 엇갈림. 영상 위 그리기는 확인 못 함 | **최소 기준선.** 여기까지는 반드시 충족하고 편집 도구로 앞서야 함 |
| Snagit | Windows·Mac | 녹화 중 화면에 그리기(Screen Draw: 화살표·도형·번호), 잘라내기, 클립 합치기, 소리 | 유료. 1시간 넘는 녹화는 권장하지 않음. 그리기 도구막대가 화면을 가릴 수 있음 | **편집 도구의 직접 경쟁 상대.** 더 많은 도구와 더 가벼운 도구막대로 앞설 부분 |
| ShareX | Windows | 무료, 영역 녹화, GIF | FFmpeg 별도 설치와 설정. 오류 보고 있음. 영상 편집 기능은 찾지 못함 | 설치·설정 없이 바로 되는 것 자체가 강점 |
| CleanShot X | Mac 전용 | 창·영역·전체 녹화, 클릭 강조, 키 입력 표시, 웹캠, GIF, 잘라내기, 녹화 중 알림 끄기 | Windows 없음 | **UI/UX의 목표.** 이번 조사에서 Windows용 같은 앱은 찾지 못함 |
| Screen Studio | Mac 전용 | 자동 확대, 커서 부드럽게, 꾸민 결과물 | Windows 없음 | 커서 움직임을 별도로 저장해야 나중에 가능 |
| FocuSee 등 | Windows·Mac | 자동 확대, 커서 강조 | 자료 대부분이 판매사·제휴 글이라 신뢰도 낮음 | 직접 확인 필요 |

**기회:** 이번 자료에서는 "스크린샷 도구의 속도 + 풍부한 주석 + 다듬은 UI"를 Windows에서 모두 갖춘 앱을 찾지 못했습니다. 다만 조사 범위가 제한적이니 단정하지는 않습니다.

## 강점별 설계 목표

수치는 **제안값**입니다. 0단계에서 실제로 재고, 경쟁 앱을 같은 PC에서 측정한 뒤 확정합니다.

### 빠른 속도

| 항목 | 목표(제안) | 방법 |
| --- | --- | --- |
| 범위 확정 → 첫 프레임 | 300ms 이내 | 인코더를 선택 화면 전에 미리 준비. 카운트다운은 기본 끔(설정에서 3초) |
| 직전 범위로 다시 녹화 | 단축키 한 번 | 스크린샷의 "직전 영역 반복"과 같은 방식 |
| 정지 → 팝업 | 500ms 이내 | 녹화 중 실시간 저장으로 후처리 대기 없음 |
| 팝업 → 다른 앱에 놓기 | 끌어 놓기 한 번 | 기존 드래그 손잡이 재사용 |
| 녹화 중 부담 | 작업에 지장 없음(기준은 측정 후) | GPU 인코더 우선, 프레임 복사 최소화, 영상 처리를 UI 스레드와 분리 |

기존 `capture-performance.jsonl`처럼 단계별 시간을 내용 없이 기록해 릴리스마다 비교합니다.

### 다양한 편집 도구

경쟁 앱과 가장 크게 차이를 낼 부분입니다. 기존 주석 렌더러를 재사용합니다.

1. **녹화 중 그리기:** 화살표, 사각형, 번호, 펜, 형광펜, Spotlight. 단축키로 "그리기"와 "화면 조작"을 전환합니다. 일정 시간 뒤 자동으로 사라지는 옵션을 둡니다.
2. **가리고 시작:** 범위를 고른 직후 비밀번호나 이름 위에 모자이크·흐림을 올려 둘 수 있습니다. 라이브 적용은 성능 시험 후 결정합니다.
3. **녹화 후 편집:** 앞뒤 잘라내기, 중간 구간 삭제, 프레임을 기존 이미지 편집기로 열기.
4. **이후 단계:** 시간 구간별 주석과 모자이크, 배경 꾸미기를 영상에 적용, 클릭 강조, 키 입력 표시, 자동 확대.

**처음부터 넣을 구조:** 커서 위치와 클릭을 별도 파일에 함께 저장합니다. 지금은 쓰지 않아도, 이게 없으면 이전 녹화에 나중 기능을 적용할 수 없습니다. 입력 내용(키 값)은 저장하지 않습니다.

### 세련된 UI/UX

- **한 가지 흐름:** 스크린샷과 같은 선택 화면을 쓰고, 상단에서 "캡처 ↔ 녹화"만 바꿉니다. 새로 배울 화면을 만들지 않습니다.
- **작은 도구막대:** 경과 시간·정지·그리기·소리 네 가지만 보이게 합니다. 범위 바깥에 두고, 포인터가 멀어지면 흐려지며, 끌어 옮길 수 있습니다. Snagit에서 지적된 "도구막대가 화면을 가리는" 문제를 피합니다.
- **상태가 명확한 녹화 표시:** 범위 모서리와 트레이 아이콘으로 표시하고, 빨간 테두리로 내용을 덮지 않습니다.
- **녹화 후 팝업:** 포인터 옆에 뜨고, 마우스를 올리면 소리 없이 재생합니다. 복사, 저장, 편집, GIF로 저장, 끌어 놓기를 스크린샷 팝업과 같은 배치로 제공합니다.
- **설정 최소화:** 기본값으로 바로 쓸 수 있게 합니다. 코덱, 비트레이트 같은 용어는 "품질: 보통·높음" 뒤로 숨깁니다.
- **일관성:** 밝게/어둡게, 아이콘, 속성 패널을 편집기와 공유합니다.

## 첫 공개 범위

| 포함 | 이후 단계 |
| --- | --- |
| 영역·창·화면 하나 녹화, 직전 범위 재녹화 | 여러 모니터에 걸친 녹화 |
| MP4 저장, 30fps 기본, 60fps 선택 | WebM |
| 커서 포함, 커서·클릭 기록 저장 | 클릭 강조, 키 입력 표시, 자동 확대 |
| 시스템 소리 | 마이크, 앱별 소리, 웹캠 |
| 녹화 중 그리기(영역·화면 녹화) | 창 녹화 중 그리기 |
| 앞뒤 잘라내기, 프레임을 이미지 편집기로 열기 | 중간 삭제, 시간 구간별 주석, 배경 꾸미기 |
| GIF로 저장(짧은 영상) | 업로드 |

## 구조

```text
WGC 프레임 풀 ─ D3D11 텍스처 ─ 영역 자르기·크기 고정 ─┐
                                                        ├─ 제한된 대기열 ─ 인코더 ─ 임시 MP4 ─ 최종 파일
WASAPI 루프백 ─ PCM ─ 무음 구간 채우기 ─────────────────┘
커서 위치·클릭 ─────────────────────────────────────────── 별도 기록 파일
```

- **`Capture.Core`:** 상태 머신, 시간 계산, 출력 크기 계산(짝수 맞춤, 최대 크기), 프레임 버림 정책, 잘라내기 구간, 커서 기록 형식. Mac에서도 테스트할 수 있습니다.
- **`Capture.Windows/Recording`:** 프레임 수집, 소리 수집, 인코더, 녹화 UI.
- **재사용:** `CaptureEngine`, 선택 화면, 단축키, `PreviewWindow`, 파일 이름 규칙, 주석 렌더러, 화면 캡처 제외 처리.

### 녹화 중 그리기

- **영역·화면 녹화:** 주석을 항상 위에 있는 투명 창에 그립니다. WGC가 화면을 그대로 찍으므로 영상에 자연히 포함됩니다. 도구막대는 캡처에서 제외합니다.
- **창 녹화:** WGC가 그 창만 찍어 위에 뜬 창이 포함되지 않습니다. 합성이 필요해 첫 공개에서는 제외하고, 창 녹화에서는 그리기 버튼을 숨깁니다.
- **입력 전환:** 그리기 모드에서는 입력을 받고, 조작 모드에서는 클릭이 아래 앱으로 통과합니다. 고정 이미지의 클릭 통과 방식을 재사용합니다.

### 인코더 선택

| 방식 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| `MediaTranscoder` + `MediaStreamSource` | 추가 패키지 없음. Microsoft 문서와 샘플이 이 조합 | 세부 제어가 적음. 소리 합치기와 오류 복구가 불투명 | **0단계에서 먼저 시험** |
| Media Foundation Sink Writer | 비트레이트·타임스탬프·하드웨어 사용을 직접 제어 | COM 연동 코드가 많음 | 첫 프레임 지연이나 동기화가 목표에 못 미치면 전환 |
| FFmpeg 포함 | 형식이 많고 사례가 많음 | 앱 크기 증가, 라이선스 고지. ShareX처럼 설정 문제 위험 | 쓰지 않음 |

HEVC는 사용자 PC에 코덱이 없을 수 있어 쓰지 않고 H.264만 지원합니다. 속도가 강점이므로 인코더 선택은 첫 프레임 지연까지 포함해 판단합니다.

### 소리

시스템 전체 소리는 기본 출력 장치의 WASAPI 루프백으로 받습니다. 앱별 소리 분리는 Windows 10 build 20348 이상에서만 가능해 첫 공개에서 뺍니다.

## Windows에서 고려할 점

| 항목 | 내용 | 대응 |
| --- | --- | --- |
| 화면 변화 없음 | WGC는 화면이 바뀔 때만 프레임을 줌 | 실제 시간 기준 타임스탬프, 일정 간격으로 마지막 프레임 반복 |
| 소리 무음 | 루프백은 소리가 없으면 데이터가 끊김 | 시간 차이만큼 무음을 채움 |
| 노란 캡처 테두리 | `IsBorderRequired` 끄기는 build 20348 이상이고 사용자 동의 필요 | Windows 11 기준으로 끄기 시도. 패키지 없는 앱에서 되는지 0단계에서 확인. UI 인상에 직접 영향 |
| 커서 | `IsCursorCaptureEnabled`는 Windows 10 2004 이상 | 앱의 대상 버전(19041)과 맞음 |
| 창 크기 변경 | 프레임 크기가 바뀜 | 프레임 풀을 다시 만들고 출력 크기는 고정 |
| 창 닫힘·최소화 | 대상이 사라지거나 프레임이 멈춤 | 닫히면 저장하고 종료. 최소화는 멈춘 화면 유지 |
| 혼합 DPI | 모니터마다 배율이 다름 | 물리 픽셀로 계산. 첫 공개는 한 모니터 안으로 제한 |
| 짝수 크기 | H.264는 가로·세로가 짝수여야 함 | 1px 줄여 맞춤 |
| 인코더 없음 | GPU 인코더가 없거나 일부 에디션에 미디어 기능이 없을 수 있음 | 시작 전 시험 후 소프트웨어 인코더, 없으면 안내. N 에디션 동작은 미확인 |
| 보호 콘텐츠 | DRM 영상과 일부 앱은 검게 찍힘 | 정상 동작으로 안내 |
| 절전·잠금 | 잠금 화면에서 프레임이 멈춤 | 녹화 중 절전 방지. 잠기면 저장하고 종료 |
| HDR | 현재 앱도 SDR만 지원 | SDR로 녹화하고 색이 다를 수 있음을 안내 |
| 비정상 종료 | MP4는 끝에 색인을 써서 중단되면 재생이 안 될 수 있음 | 임시 파일에 기록. 복구 가능성은 0단계에서 확인 |
| 디스크 부족 | 긴 녹화 중 공간 부족 | 주기적으로 확인해 부족하면 저장하고 종료 |
| 성능 저하 | 인코더가 못 따라가면 지연 누적 | 대기열 크기 제한, 프레임 버림과 기록 |
| 자체 UI | 도구막대가 영상에 찍히면 안 됨 | `SetWindowDisplayAffinity`로 제외. 실기기 확인 필요 |
| 개인정보 | 소리와 화면이 함께 저장됨 | 로컬 저장만, 녹화 중 표시 필수, 소리 포함 여부 표시. 커서 기록에 키 값 없음 |

## 단계

크기는 상대값입니다. 0단계 결과에 따라 달라지므로 날짜는 정하지 않습니다.

| 단계 | 내용 | 크기 | 완료 기준 |
| --- | --- | --- | --- |
| 0. 기술·경쟁 시험 | 시험 명령으로 1080p 30초를 소리와 함께 저장. 시작 지연 측정. 캡처 도구·Snagit·ShareX를 같은 PC에서 비교 | 작음 | "결정 기준" 확인, 속도 목표 확정 |

| 3. 소리 | 루프백, 무음 채우기, 동기화, 장치 변경 | 큼 | 10분 녹화에서 소리가 어긋나지 않음 |
| 4. 녹화 중 그리기 | 투명 주석 창, 입력 전환, 도구 재사용 | 중간 | 그린 내용이 영상에 포함되고 도구막대는 제외 |
| 5. 녹화 후 편집 | 잘라내기, 프레임을 편집기로, GIF 저장 | 중간 | 결과 파일이 재생되고 원본은 보존 |
| 6. 안정화·공개 | 오류 복구, 디스크 부족, 창 변화, 긴 녹화, 실기기 목록 | 중간 | 아래 목록 통과 후 릴리스 |
| 이후 | 구간별 주석·모자이크, 배경 꾸미기, 클릭 강조, 키 표시, 자동 확대, 마이크, 웹캠 | 항목별 | 첫 공개 사용 후 결정 |

중간 시험판은 2단계와 3단계 뒤에 낼 수 있습니다. 정식 안내는 4·5단계까지 끝난 뒤 하는 것을 권합니다. 그 전에는 캡처 도구와 차이가 크지 않기 때문입니다.

### 0단계 결정 기준

- 영상과 소리가 함께 저장되고 Windows 기본 재생기와 브라우저에서 재생되는가
- 10분 녹화에서 소리가 눈에 띄게 어긋나지 않는가
- 인코더를 미리 준비했을 때 첫 프레임 지연이 목표에 근접하는가
- 1080p 30fps에서 CPU·GPU 부담이 작업에 지장이 없는가
- 패키지 없는 설치형 앱에서 테두리를 끌 수 있는가
- 도구막대는 영상에서 제외되고 주석 창은 포함되는가
- GPU 인코더가 없는 환경에서 어떻게 되는가

앞의 세 항목을 내장 방식으로 충족하지 못하면 Sink Writer로 전환합니다.

## 검증

- **CI로 가능:** 상태 머신과 시간 계산, 커서 기록 형식, 합성 프레임으로 만든 MP4의 길이·크기 검사(러너에서 인코더가 동작하는지 먼저 확인 필요).
- **CI로 불가능:** 실제 화면 수집, 시스템 소리, GPU 인코더, 테두리, 체감 속도, 그리기 입력 전환.
- **실기기 목록:** 화면 전체·영역·창 / 혼합 DPI / 창 크기 변경·닫기·최소화 / 소리 있음·없음·장치 변경 / 정적 화면 10분 / 움직이는 영상 10분 / 그리기와 조작 전환 / 잠금·절전 / 디스크 부족 / 강제 종료 / GPU 인코더 없는 PC.

## 정할 것

제안 기본값입니다. 다르게 원하시면 0단계 전에 정하면 됩니다.

1. 기본 품질: 30fps, 원본 해상도, 시스템 소리 끔
2. 카운트다운: 기본 끔. 속도를 우선하되 범위를 고른 직후 시작이 어색하면 시험 후 조정
3. 저장 위치: 기존 저장 폴더와 파일 이름 규칙
4. 종료 후: 포인터 옆 팝업. 클립보드에는 파일로 복사
5. 첫 대상 OS: Windows 11 x64. Windows 10은 테두리가 남는 상태로 허용
6. 공개 시점: 4·5단계까지 끝난 뒤 정식 안내
