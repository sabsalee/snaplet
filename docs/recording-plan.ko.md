# 동영상 녹화 계획

작성일: 2026-11-06. 상태: 제안. 아직 코드를 쓰지 않았고, 프로토타입도 돌려 보지 않았습니다.

## 결론

- **기준 앱에는 녹화 기능이 없습니다.** 공식 안내는 화면을 "녹화"하지 않고 스크린샷만 찍는다고 설명하고, 바이너리 문자열에도 영상 인코딩이나 녹화 저장 흔적이 없습니다. 움직이는 결과물은 두 프레임짜리 "Before/After GIF"뿐입니다. 맞출 대상이 없으므로 Snaplet의 독자 기능으로 설계합니다.
- **첫 버전은 MP4(H.264 + AAC) 녹화 하나에 집중합니다.** 영역·창·화면 중 하나를 녹화하고, 커서와 시스템 소리를 포함하며, 끝나면 기존 팝업으로 결과를 보여 줍니다.
- **인코딩은 Windows 내장 기능으로 시작합니다.** 이 앱은 이미 Windows Graphics Capture(WGC)를 쓰고 있어 화면 프레임을 받는 부분을 이어 쓸 수 있습니다. 추가 인코더를 포함하지 않아 앱 크기가 거의 늘지 않습니다.
- **코드를 쓰기 전에 실기기 시험을 먼저 합니다.** 이 프로젝트의 CI는 실제 화면·소리·GPU를 검증하지 못하므로, 위험한 부분은 0단계에서 실제 PC로 확인합니다.

## 첫 버전 범위

| 포함 | 제외 (이후 단계) |
| --- | --- |
| 영역·창·화면 하나 녹화 | 여러 모니터에 걸친 녹화 |
| MP4 저장, 30fps 기본, 60fps 선택 | GIF·WebM 내보내기 |
| 커서 포함 켜기/끄기 | 클릭 강조, 키 입력 표시 |
| 시스템 소리 켜기/끄기 | 마이크, 앱별 소리 분리 |
| 시작/정지 단축키, 일시정지 없음 | 일시정지, 웹캠 |
| 3초 카운트다운, 녹화 중 표시 | 영상 위 그리기, 잘라내기 편집 |
| 종료 후 팝업(폴더 열기·복사·드래그) | 업로드 |

## 사용 흐름

1. 단축키, 트레이 메뉴 또는 메인 창에서 "화면 녹화"를 고릅니다. 새 명령이므로 다른 명령처럼 기본 단축키는 비워 둡니다.
2. 기존 선택 화면에서 영역을 드래그하거나 창을 클릭합니다. Enter는 현재 화면 전체입니다.
3. 3초 카운트다운 뒤 시작합니다. 영역 테두리와 작은 도구막대(경과 시간, 소리 표시, 정지)를 띄웁니다. 이 둘은 영상에 찍히지 않아야 합니다.
4. 같은 단축키, 정지 버튼 또는 트레이 아이콘으로 끝냅니다.
5. 설정의 저장 폴더와 파일 이름 규칙으로 저장하고, 포인터 옆 팝업을 띄웁니다. 첫 프레임 썸네일, 길이·용량, 폴더 열기, 파일 복사, 끌어서 놓기를 제공합니다.

## 구조

```text
WGC 프레임 풀 ─ D3D11 텍스처 ─ 영역 자르기·크기 고정 ─┐
                                                        ├─ 제한된 대기열 ─ 인코더 ─ 임시 MP4 ─ 최종 파일
WASAPI 루프백 ─ PCM ─ 무음 구간 채우기 ─────────────────┘
```

- **`Capture.Core`:** 플랫폼과 무관한 부분입니다. 상태 머신(대기·카운트다운·녹화·마무리·실패), 시간 계산, 출력 크기 계산(짝수 맞춤, 최대 크기), 프레임 버림 정책을 둡니다. Mac에서도 테스트할 수 있습니다.
- **`Capture.Windows/Recording`:** 프레임 수집, 소리 수집, 인코더, 녹화 UI를 둡니다.
- **재사용:** `CaptureEngine`의 WGC 항목·D3D 장치 생성, 선택 화면, 단축키, `PreviewWindow`, 파일 이름 규칙, 화면 캡처 제외 처리.

### 인코더 선택

| 방식 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| `MediaTranscoder` + `MediaStreamSource` | 추가 패키지 없음. Microsoft 문서와 샘플이 이 조합. D3D 표면을 그대로 넘김 | 세부 제어가 적음. 소리 합치기와 오류 복구가 불투명 | **0단계에서 먼저 시험** |
| Media Foundation Sink Writer | 비트레이트·타임스탬프·하드웨어 사용을 직접 제어 | COM 연동 코드가 많음 | A가 소리 동기화나 성능에서 실패하면 전환 |
| FFmpeg 포함 | 형식이 많고 문제 해결 사례가 많음 | 수십 MB 증가, 라이선스 고지, 프로세스 관리 | 쓰지 않음 |

HEVC는 쓰지 않습니다. 사용자 PC에 따라 코덱이 없을 수 있어 H.264만 지원합니다.

### 소리

시스템 전체 소리는 기본 출력 장치의 WASAPI 루프백으로 받습니다. 직접 COM 코드를 쓰거나 NAudio를 쓰는 방법 중 0단계에서 고릅니다. 앱별 소리 분리(프로세스 루프백)는 Windows 10 build 20348 이상에서만 가능해 첫 버전에서 뺍니다.

## Windows에서 고려할 점

| 항목 | 내용 | 대응 |
| --- | --- | --- |
| 화면 변화 없음 | WGC는 화면이 바뀔 때만 프레임을 줌 | 실제 시간 기준 타임스탬프를 쓰고, 재생기 호환을 위해 일정 간격으로 마지막 프레임을 반복 |
| 소리 무음 | 루프백은 아무 소리도 안 나면 데이터가 끊김 | 시간 차이만큼 무음을 채워 영상과 길이를 맞춤 |
| 노란 캡처 테두리 | `IsBorderRequired` 끄기는 build 20348 이상이고 사용자 동의가 필요 | Windows 11 기준으로 끄기 시도. 설치형(패키지 없는) 앱에서 되는지 0단계에서 확인 |
| 커서 | `IsCursorCaptureEnabled`는 Windows 10 2004 이상 | 앱의 대상 버전(19041)과 맞음 |
| 창 크기 변경 | 녹화 중 창이 커지거나 줄면 프레임 크기가 바뀜 | 프레임 풀을 다시 만들고 출력 크기는 고정해 맞춰 넣음 |
| 창 닫힘·최소화 | 대상이 사라지거나 프레임이 멈춤 | 닫히면 저장하고 종료. 최소화는 멈춘 화면 유지 |
| 혼합 DPI | 모니터마다 배율이 다름 | 물리 픽셀로 계산. 첫 버전은 한 모니터 안으로 제한 |
| 짝수 크기 | H.264는 가로·세로가 짝수여야 함 | 1px 줄여 맞춤 |
| 인코더 없음 | GPU 인코더가 없거나 일부 Windows 에디션에 미디어 기능이 없을 수 있음 | 시작 전 시험 후 소프트웨어 인코더로 전환, 없으면 안내. N 에디션 동작은 미확인 |
| 보호 콘텐츠 | DRM 영상과 일부 앱은 검게 찍힘 | 정상 동작으로 안내 |
| 절전·잠금 | 잠금 화면에서 프레임이 멈춤 | 녹화 중 절전 방지. 잠기면 저장하고 종료 |
| HDR | 현재 앱도 SDR만 지원 | SDR로 녹화하고 HDR 화면에서 색이 다를 수 있음을 안내 |
| 비정상 종료 | MP4는 끝에 색인을 써서 중단되면 재생이 안 될 수 있음 | 임시 파일에 기록. 복구 가능성은 0단계에서 확인 |
| 디스크 부족 | 긴 녹화 중 공간이 부족할 수 있음 | 주기적으로 확인해 부족하면 저장하고 종료 |
| 성능 저하 | 인코더가 못 따라가면 지연 누적 | 대기열 크기를 제한하고 프레임을 버림. 버린 수를 기록 |
| 자체 UI | 도구막대가 영상에 찍히면 안 됨 | 현재 팝업처럼 `SetWindowDisplayAffinity`로 제외. 실기기 확인 필요 |
| 개인정보 | 소리와 화면이 함께 저장됨 | 로컬 저장만, 녹화 중 표시 필수, 소리 포함 여부를 도구막대에 표시 |

## 단계

크기는 상대값입니다. 0단계 결과에 따라 달라지므로 날짜는 정하지 않습니다.

| 단계 | 내용 | 크기 | 완료 기준 |
| --- | --- | --- | --- |
| 0. 기술 시험 | 별도 시험 명령으로 1080p 화면 30초를 소리와 함께 MP4 저장 | 작음 | 아래 "결정 기준"을 실제 PC에서 확인 |
| 1. 영상만 | 영역·창·화면 녹화, 커서, 저장, 상태 머신과 테스트 | 큼 | 소리 없는 MP4가 표준 재생기에서 재생됨 |
| 2. 사용 흐름 | 명령·단축키·트레이, 카운트다운, 테두리·도구막대, 종료 후 팝업, 설정 | 중간 | 흐름 전체가 실제 PC에서 동작 |
| 3. 소리 | 루프백, 무음 채우기, 동기화, 장치 변경 처리 | 큼 | 10분 녹화에서 소리가 어긋나지 않음 |
| 4. 안정화 | 오류 복구, 디스크 부족, 창 변화, 긴 녹화, 릴리스 | 중간 | 아래 실기기 목록 통과 |
| 이후 | 마이크, GIF 내보내기, 잘라내기, 클릭 강조, 일시정지 | 항목별 | 첫 버전 사용 후 결정 |

### 0단계 결정 기준

- 영상과 소리가 함께 저장되고 Windows 기본 재생기와 브라우저에서 재생되는가
- 10분 녹화에서 소리가 눈에 띄게 어긋나지 않는가
- 1080p 30fps에서 CPU·GPU 부담이 작업에 지장이 없는가. 기준 수치는 첫 측정 후 정함
- 패키지 없는 설치형 앱에서 테두리를 끌 수 있는가
- 도구막대가 영상에서 제외되는가
- GPU 인코더가 없는 환경에서 어떻게 되는가

처음 두 항목을 내장 방식으로 충족하지 못하면 Sink Writer로 전환합니다.

## 검증

- **CI로 가능:** 상태 머신과 시간 계산 테스트, 합성 프레임을 인코더에 넣어 만든 MP4의 길이·크기 검사(러너에서 인코더가 동작하는지 먼저 확인 필요).
- **CI로 불가능:** 실제 화면 수집, 시스템 소리, GPU 인코더, 테두리, 성능.
- **실기기 목록:** 화면 전체·영역·창 / 혼합 DPI / 창 크기 변경·닫기·최소화 / 소리 있음·없음·중간에 장치 변경 / 정적 화면 10분 / 움직이는 영상 10분 / 잠금·절전 / 디스크 부족 / 강제 종료 / GPU 인코더 없는 PC.

## 정할 것

제안 기본값입니다. 다르게 원하시면 0단계 전에 정하면 됩니다.

1. 기본 품질: 30fps, 원본 해상도, 시스템 소리 끔
2. 저장 위치: 기존 저장 폴더, 파일 이름은 기존 규칙(필요하면 영상용 규칙 분리)
3. 종료 후: 포인터 옆 팝업. 클립보드에는 파일로 복사
4. 첫 대상 OS: Windows 11 x64. Windows 10은 테두리가 남는 상태로 허용
